# A-10 satisfaction collection TDD record

## Scope

A-10 stores a 1–5 satisfaction rating and optional comments for the correct project after a
proposal exists. It does not add participant identities, analytics dashboards, authentication,
comment-length policy, or invented validation evidence.

## Red phase

Commit `f4ec03d` added the tests before production behavior:

- 8 FastAPI contract cases for the route, strict integer type, required rating, and 1–5 bounds.
- 11 backend integration cases for persistence, both valid boundaries, optional and Unicode text,
  invalid-rating atomicity, unknown projects, proposal completion, project isolation, and reload.
- 5 React cases for successful submission, optional text, required rating, duplicate-submit
  prevention, and recoverable API errors.

The backend cases failed because the route, service, and repository did not exist. The frontend
suite failed because `FeedbackForm` did not exist. These were the expected A-10 failures.

## Green phase

- Added the `SatisfactionFeedback` domain model.
- Added migration `0008_satisfaction_feedback` with a project foreign key and database-level 1–5
  rating constraint.
- Added `SqlFeedbackRepository` and `FeedbackService`.
- Required a real project and an existing proposal before accepting feedback.
- Added `POST /projects/{project_id}/feedback` with Pydantic `StrictInt` validation.
- Added the React feedback form after the export stage, including a synchronous submission lock.
- Extended the Playwright happy path to submit project-linked satisfaction feedback.

## Verification

- Focused A-10 backend: 21 passed, including post-green exception-mapping checks.
- Complete backend deterministic suite: 267 passed, 3 conditional skips, 1 real-model test
  deselected.
- Complete frontend suite: 53 passed.
- Frontend production build: passed.
- Alembic upgrade through `0008` and downgrade to `0007`: passed on a temporary SQLite database.
- Offline Playwright suite: passed with no failed tests; the real OpenCLIP/Groq scenario remains
  separately gated by credentials and model availability.

No participant, rating, or validation result is generated by the application. A response exists
only after a user submits the form for a project with a stored proposal.
